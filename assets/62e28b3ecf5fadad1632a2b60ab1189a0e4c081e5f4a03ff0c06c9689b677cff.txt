# AES round-key memory

Implement module `aes_key_mem`, with no parameters. Inputs: `clk`, active-low asynchronous `reset_n`, `key[255:0]`, `keylen`, `init`, `round[3:0]`, and `new_sboxw[31:0]`. Outputs: `round_key[127:0]`, `ready`, `sboxw[31:0]`. Updates occur on the rising clock edge. This is a key-expansion component with an external, combinational word S-box interface; do not include an S-box or assume its response is correct. Every value of `new_sboxw` affects expansion as specified.

Reset clears fifteen128-bit key entries, both128-bit history words P0/P1, four-bit round counter R, and eight-bit round constant C; sets ready=1 and control=idle. `round_key` reads entry `round` combinationally, even during expansion. Index15 addresses no storage and has no defined data value. `sboxw` is always P1[31:0], including idle/reset. Entries not overwritten retain their previous values.

An idle edge with init=1 sets ready=0 and enters initialization. The next edge sets R=0 and enters generation. Each generation edge writes entry R if R<=14 (R=15 has no storage entry and leaves memory unchanged), increments R modulo16, and enters done when pre-edge R equals10 for keylen=0 or14 for keylen=1. A done edge sets ready=1 and returns idle. Init is ignored outside idle. With stable keylen, entry0 is written two edges after acceptance, and ready returns13 edges after acceptance for AES-128 or17 for AES-256. Holding init high starts another operation on the next idle edge. Key/keylen are live, not latched; changes use current values at each generation edge, including termination.

Split P0 into most-significant-first32-bit words a,b,c,d and P1 into e,f,g,h. Let S=new_sboxw and T=rotate_left_bytes(S,1) XOR (C<<24). Equations use pre-edge values. Outside generation C becomes0x8d each edge. In generation C holds except listed advances; advance means `(C<<1) XOR (0x1b if C[7] else0)`, truncated to8 bits.

| Mode / round | New entry, MSW first | History update | Advance C |
|---|---|---|---|
| keylen=0,R=0 | key[255:128] | P1=new; P0 holds | yes |
| keylen=0,R>0 | e XOR T; f XOR e XOR T; g XOR f XOR e XOR T; h XOR g XOR f XOR e XOR T | P1=new; P0 holds | yes |
| keylen=1,R=0 | key[255:128] | P0=new; P1 holds | no |
| keylen=1,R=1 | key[127:0] | P1=new; P0 holds | yes |
| keylen=1,R>=2 even | a XOR T; b XOR a XOR T; c XOR b XOR a XOR T; d XOR c XOR b XOR a XOR T | P0=old P1; P1=new | no |
| keylen=1,R>=2 odd | preceding equation with S replacing T | P0=old P1; P1=new | yes |

Normal use keeps key/keylen stable and supplies AES byte substitutions externally. The live-input and idle behavior remains part of the contract; no formal assumptions hide changes or arbitrary S-box responses.

Live keylen changes can miss both normal terminal comparisons and reach R=15; the history, round-constant and modulo16 counter updates still follow the generation rules while that nonexistent memory write is ignored.
