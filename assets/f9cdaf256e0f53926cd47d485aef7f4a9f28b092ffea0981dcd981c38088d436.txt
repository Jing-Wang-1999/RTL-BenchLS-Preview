Module Specification: Long to Double Converter

Overview
This module converts a 64-bit signed integer into a 64-bit IEEE 754 double-precision floating-point number. It operates synchronously with a system clock and utilizes a handshake protocol for data flow control on both input and output interfaces. The design is self-contained and does not instantiate any external sub-modules.

Interface Description
Clock: A global timing signal. All state changes and data updates occur on the rising edge.
Reset: A synchronous control signal. When active, the module initializes to its default idle state.

Input Port:
- Data: A 64-bit bus carrying the signed integer value to be converted.
- Valid: A signal indicating the input data is stable and ready for processing.
- Acknowledge: A signal asserted by the module to indicate it is ready to accept new input data.

Output Port:
- Data: A 64-bit bus carrying the resulting floating-point value.
- Valid: A signal asserted by the module to indicate the output data is stable and ready for consumption.
- Acknowledge: A signal from the downstream consumer indicating the output data has been received.

Handshake Protocol
The module implements a full handshake mechanism to ensure reliable data transfer.
Input Transaction: The module asserts the input acknowledge signal when idle. A transaction is completed when both the input valid and input acknowledge signals are high simultaneously. Upon acceptance, the acknowledge signal is temporarily deasserted during processing.
Output Transaction: The module asserts the output valid signal when conversion is complete. The output data remains stable until the downstream consumer asserts the output acknowledge signal. Once acknowledged, the module deasserts the valid signal and prepares for the next conversion.

Conversion Algorithm
The conversion process follows a sequential state machine:
1. Acquisition: The module waits for an input transaction. Once accepted, the integer value is stored internally.
2. Zero Detection: If the input value is zero, the output is set to positive zero immediately, bypassing calculation.
3. Sign and Magnitude: The most significant bit of the input determines the sign of the floating-point result. If the input is negative, the two's complement magnitude is calculated.
4. Normalization: The magnitude is shifted left until the most significant bit is one. The exponent is decremented for each shift operation. Bits shifted out are preserved for rounding.
5. Rounding: The module applies Round to Nearest, Ties to Even logic. It uses guard, round, and sticky bits derived from the normalization shift. If rounding causes the mantissa to overflow, the exponent is incremented.
6. Packing: The final sign, biased exponent (using a bias of 1023), and 52-bit fraction are assembled into the standard IEEE 754 double-precision format.
7. Delivery: The packed result is placed on the output data port. The module waits for the output acknowledge before returning to the Acquisition state.

Reset Behavior
When the reset signal is active during a clock edge, the module forces the state machine to the Acquisition state. All handshake signals are deasserted, and internal data registers are cleared. This ensures a known safe state upon initialization.

Internal Structure
The logic is implemented using a finite state machine and internal data registers. There are no instantiated sub-modules. All arithmetic and control logic resides within this single unit. The design supports multi-cycle operation, meaning the conversion takes several clock cycles to complete depending on the normalization required.
