**Module Specification: rtlpp_07504 – Phase Increment Generator**

**Overview**  
This module computes a signed 16-bit phase increment value for a digital oscillator or frequency generator. It combines a base frequency number, octave scaling, a multiplier factor, and optional vibrato modulation to produce the final phase step per sample clock.

**Inputs**  
- **rst**: Active-high synchronous reset.  
- **clk**: Main system clock; all synchronous operations occur on its rising edge.  
- **sample_clk_en**: Enables sampling/updates (assumed to be used externally; not directly consumed in the provided logic).  
- **fnum[7:0]**: Unsigned 8-bit base frequency number.  
- **mult[3:0]**: Unsigned 4-bit multiplier selector.  
- **block[2:0]**: Unsigned 3-bit octave/block value for frequency scaling.  
- **vib**: Vibrato enable; when high, adds a vibrato offset to the phase increment.  
- **dvb**: (Note: This input is present but unused in the provided logic; its function is unspecified.)

**Outputs**  
- **phase_inc[15:0]**: Signed 16-bit phase increment, updated combinationally based on current inputs and registered state.

**Internal Processing**  
1. **Pre‑scaling**: The base frequency number (`fnum`) is left‑shifted by the `block` value, producing a 16‑bit intermediate value (`pre_mult`). This scales the frequency by a factor of \(2^{\text{block}}\).  

2. **Multiplier Adjustment**:  
   - A combinational lookup table maps the 4‑bit `mult` input to a signed 4‑bit adjustment factor (`pre_mult_adj`). The mapping is:  
     - `mult` = 0 or 1 → factor = 1  
     - `mult` = 2 → 2, 3 → 3, … 9 → 9, A or B → 10, C or D → 12, E or F → 15.  
   - Synchronously, when `mult` is 0, the shifted `pre_mult` is right‑shifted by one (division by 2). For all other `mult` values, `pre_mult` is multiplied by the adjustment factor, yielding a signed 16‑bit registered result (`post_mult`). Reset clears `post_mult` to zero.

3. **Vibrato Addition**:  
   - A registered 8‑bit vibrato offset (`vib_val`) is maintained (reset to zero). Its update mechanism is not defined in the provided logic.  
   - Combinational logic adds `vib_val` to `post_mult` when `vib` is high; otherwise, `phase_inc` equals `post_mult` directly.
