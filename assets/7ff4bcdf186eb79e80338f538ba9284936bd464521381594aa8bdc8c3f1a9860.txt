# rtlpp_04967: default-configuration specification

Implement an eight-bit AXI-stream Ethernet FCS checker/remover. There are no parameters. Rising clk updates all state; synchronous high rst clears state to IDLE, input ready, busy, bad-FCS pulse, four delayed-byte valid bits, both output-buffer valid bits and registered internal ready; CRC becomes FFFFFFFF. Payload data and LAST/USER storage are not reset, and their invalid-cycle values have no zero guarantee. Source declaration initializers are not a required power-up contract.

Keep four previously accepted input bytes d0(newest)..d3(oldest), each with a valid bit. On input VALID and registered input READY, shift input DATA into d0 and the preceding bytes toward d3. A normal packet emits d3 for each new input after the four-byte look-behind fills, removes the final four bytes, and marks only the final emitted payload byte LAST. Busy is the registered predicate that next state is PAYLOAD; it stays low during initial four-byte filling, even though bytes are accumulating.

CRC uses reflected Ethernet recurrence: for each bit of d3, bit0 first, XOR that bit with CRC bit0, shift CRC right, and XOR EDB88320 when that XOR is1. Start from FFFFFFFF. In IDLE request CRC reset every cycle, except an accepted input with d3 valid updates CRC and enters PAYLOAD. PAYLOAD holds until an accepted LAST and otherwise updates CRC on every accepted byte. On an accepted LAST with d3 valid in either state, compare the concatenation {current input byte,d0,d1,d2} with complemented next CRC (including d3). Mismatch emits a one-cycle error_bad_fcs pulse and forces final USER1; otherwise final USER equals current input USER. Clear all four delayed valid bits, reset CRC and return IDLE. LAST while fewer than four delayed bytes are valid is ignored: it neither flushes the bytes nor creates output or an error. This module has no short-frame checker; describe and preserve that behavior without imposing a formal input restriction. Nonfinal input USER is ignored.

In either legal state, internal output DATA=d3 and internal VALID=delayed-valid3 AND current input VALID; LAST and USER default0 and become final values only on an accepted LAST as above. DATA registers shift whenever the combinational acceptance predicate is true, even on a reset edge, although reset clears delayed valid bits. In IDLE input READY next is the early output-buffer readiness; in PAYLOAD it is the same. All assignments use preedge state.

Output buffering has a primary and temporary entry containing DATA/VALID/LAST/USER. Early readiness is output READY OR (temporary invalid AND (primary invalid OR internal invalid)); register it each nonreset edge. If old registered internal readiness is1, copy internal payload to primary when external READY or primary invalid, otherwise to temporary; replace that destination VALID with internal VALID. If old internal readiness is0 but external READY1, move temporary payload and VALID into primary and clear temporary VALID. Otherwise hold both. Payload copies are not reset-gated, while reset overrides VALID/readiness. This preserves one-entry backpressure buffering, stable valid output under stall and exact invalid payload updates.
