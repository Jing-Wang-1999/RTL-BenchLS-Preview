# hsci_mdec: default-configuration specification

Implement the module interface below. All arithmetic is fixed-width unsigned unless explicitly stated. Sequential updates use pre-edge values and occur on the stated clock edge. Preserve externally observable cycle timing, including outputs outside valid transactions wherever defined. No golden RTL is provided to the implementation model.

## Interface

```verilog
module hsci_mdec (
  
  input hsci_pclk,
  input rstn,
  
  input frm_det,
  input next_frm_start,
  input [9:0] mdec_sfrm,
  input mdec_val,
  output reg [1:0] rd_tsize,
  
  output reg [14:0] dec_addr,
  output reg [31:0] dec_data,
  output reg dec_en,
  output reg [3:0] dec_we,
  
  input miso_test_mode,
  output [2:0] dec_fsm,
  output reg [7:0] error_code,
  input clear_errors,
  output reg parity_err,
  output reg unk_instr_err,
  
  input ver_b_na,
  input man_linkup,
  input auto_linkup,
  input [3:0] alink_fsm,
  output reg alink_dval,
  output reg [7:0] alink_data,
  output reg signal_det,
  output reg signal_acquired,
  output idle_state,
  output reg [3:0] tx_clk_adj_rcvd,
  output reg tx_clk_inv_rcvd,
  
  input [3:0] menc_state,
  input xfer_mode,
  input read_op,
  input [16:0] read_byte_num,
  output reg read_done
);
endmodule
```

## HSCI subframe decoder

Rising `hsci_pclk`, asynchronous low `rstn`. A subframe supplies word W=`mdec_sfrm[9:2]`, parity P=bit1 and continuation C=bit0. `mdec_val` qualifies FSM/data consumption, but **parity checking runs every clock regardless of valid**: mismatch between P and XOR of all eight W bits plus C sets sticky `parity_err`, with mismatch winning over clear_errors. This detector does not suppress decoding/writes.

FSM output `dec_fsm` codes are idle0, instruction1, read-index2, read-data3, error4, linkup5, test6, unknown-message7. Reset enters idle and clears all state described below except `rd_tsize`, which has no reset assignment and remains unspecified until sampled in idle with frame-detect. `idle_state=(state==idle && auto_linkup)`.

## State transitions and decoded sidebands

In idle with valid, priority is test mode→test; manual linkup→idle; auto linkup→linkup only when W7=1 and W6:3=5; otherwise normal mode accepts W7=1 with opcode A→read-index, C→error, other→unknown-message, or stays idle if W7=0. Instruction state (not normally reached after reset) performs the same A/C/unknown opcode dispatch on valid start-bit words. Read-index stays until valid C=0, then read-data. Read-data returns idle on valid C=0, independent of `next_frm_start`; otherwise stays. Linkup returns idle on valid C=0. Error and unknown-message return idle on any valid subframe. Test stays until miso_test_mode clears. No valid means hold except idle/test rules above.

`signal_det` latches frame-detect while auto_linkup=1 and clears when auto_linkup=0. In idle, auto-linkup plus ver_b_na captures clock adjustment `{W[1:0],P,C}` and inversion W2 whenever W7/opcode5 match, without mdec_val gating. In auto-linkup with ver_b_na=0 those adjustment outputs clear. Outside auto-linkup, idle+frm_det captures rd_tsize=W1:0. The adjustment outputs otherwise hold.

In linkup, latch `signal_acquired=1` permanently until reset. Each valid subframe sets alink_dval1 and alink_data=W; invalid sets dval0 and leaves data. Idle clears alink_dval and data to0. Other states hold these registers, so there is no independent universal pulse clear outside linkup/idle.

In error on a valid subframe, error_code captures W, with priority over clear_errors; otherwise clear_errors clears it. In unknown-message on valid, set sticky unk_instr_err with priority over clear. Both reset0. Errors are reporting outputs rather than decode aborts.

## Read data and memory writes

Maintain a 32-bit index accumulator and 2-bit saturating index-byte counter. Idle clears accumulator/count. In read-index on valid, store W in successive little-endian byte positions, saturating at position3. The accumulated index is not connected to public memory address in this implementation.

Maintain a 2-bit data-lane counter. Reset clears it; idle clears it only while read_done=1, otherwise retains it across read frames. In read-data on valid, produce a one-cycle internal store flag, place W in the selected byte lane of a zero-filled32-bit word, set one-hot lane mask1/2/4/8, and increment lane modulo4. Read-data without valid clears the store flag and retains mask/data. Idle/instruction clear store and mask; other states hold them.

One clock later, if the old store flag is1, `dec_en=1`, `dec_we=old lane mask`, `dec_data=old zero-filled word`, and address normally holds. Otherwise dec_en/we/data clear; if menc_state=0, address also clears. This is a registered pulse interface with no ready input.

Address is a 15-bit word index starting0. Independently, old `dec_we[3]` increments address modulo32768 and sets a new-address flag, taking priority over ordinary address hold/clear. During a stored byte, old dec_we[0] clears that flag. At read completion's second high cycle, discontinuous xfer_mode1 advances to a new word unless the new-address flag says a lane3 write already did so (then clear flag); contiguous xfer_mode0 clears address and the flag. Apply these later address overrides after the basic memory-output updates.

## Read completion counter

Reset clears 17-bit byte count, read_done and its one-cycle delayed copy. Every edge delay read_done. `read_op` has highest priority: clear byte count/read_done and mark internal pending. Otherwise old store flag increments count. Otherwise if count>`read_byte_num`, clear count/pending and assert read_done. Thus the input is the **zero-based last-byte count**, not the literal number of bytes, and completion comparison happens on a nonstore edge. Otherwise if delayed read_done=1 clear read_done; otherwise hold it. In ordinary use read_done lasts two clocks. Pending is internal and does not gate counting or completion; no hidden read_pending assumption may be added. `next_frm_start` has no effective influence in the declared implementation. The public input `alink_fsm` is unused and has no effect on any output.

The memory data path, protocol errors and link training remain active in the sole default configuration. No speculative correction of ungated parity or unused received index is part of this task.
