SLAVE='''Implement TOP and i2c_slave as one complete I2C-controlled BUS bridge. This design is an I2C SLAVE that initiates BUS accesses; it is independent of the I2C master controllers, whose traffic direction and external contract are different.

- Read the unchanged original protocol comment block in specification/rtl_protocol_comments.md. Enable the slave with enable and its exact seven-bit device_address; the wrapper sets an all-ones address mask. Filter SCL/SDA input glitches according to FILTER_LEN. Use open-drain outputs and external resolved input feedback. The slave may hold SCL low to wait for its ready/valid data endpoints; never actively drive either serial line high.
- An I2C write begins with a big-endian address prefix (most significant address byte first), followed by data bytes in increasing byte-address order. Stop or repeated-start terminates the write, flushing a partial word. Set the pointer with an address-only write, then issue a repeated-start I2C read to fetch from that location. Data bytes within the bus word are little-endian, starting at the offset encoded by the pointer.
- CURATOR CORRECTION: the upstream comment's formula has an erroneous outer log2. The number of address-prefix bytes is ceil(ADDR_WIDTH_ADJ/8), where ADDR_WIDTH_ADJ=BUS_ADDR_WIDTH+log2((BUS_DATA_WIDTH/BUS_SELECT_WIDTH)/8). For the qualified eight-bit-byte,16-bit-address configuration, this is exactly TWO address bytes, not one. Use the adjusted width for general declaration parameters.
- Coalesce writes to one aligned bus word until that word is complete or I2C terminates. Drive byte selects only for received bytes, leaving neighboring bytes unmodified; unused payload lanes can contain zero. Coalesce reads into one bus read per aligned word and serialize its data bytes. The internal pointer advances at completed bus-word boundaries; do not infer a precise per-byte pointer value after terminating a partial read. Software should set the address prefix before each transfer whose start matters.
- BUS_CONTRACT
- i2c_slave uses AXI-stream-style data ready/valid internally: m_axis_data carries bytes received from I2C with last on transaction end; s_axis_data supplies bytes to transmit. Keep bytes stable while stalled, honor external ACK/NACK and stop/repeated-start events, and release lines when disabled or reset. busy/bus_addressed/bus_active report protocol progress. Reset clears pending protocol/bus-valid state; do not rely on a previously programmed pointer after reset.
- Qualification uses the original32-bit bus data,16-bit byte address and FILTER_LEN=4 wrapper bench plus the separate original i2c_slave bench.
