Implement arp, arp_cache, arp_eth_rx, arp_eth_tx and lfsr at the declared paths. The unchanged original README describes this independent ARP subsystem; original_packet_documentation.md preserves the original frame format and LFSR documentation. The full Ethernet/IP/UDP stack is outside this project. The declaration-only interfaces contain all required ports and parameters.

## Reviewed clarifications
- All sequential interfaces use rising clk edges and active-high synchronous rst. Ethernet headers and AXI-stream payload use their separate valid/ready handshakes. Byte lane zero is the earliest byte, with each multi-byte ARP field transmitted in network byte order. tkeep marks active byte lanes; tlast ends a packet; tuser marks an invalid input frame. Preserve valid payload while stalled, except for the lookup-response limitation below.
- arp_eth_rx decodes the original documented 28-byte Ethernet/IPv4 ARP payload into parallel fields, detects early termination and invalid HLEN/PLEN, drains padding and rejects bad frames. arp_eth_tx performs the converse, inserts HLEN=6 and PLEN=4, and marks the final valid payload bytes using tkeep/tlast. The parallel Ethernet header is supplied separately and is not repeated in the payload.
- The integration top accepts Ethernet type 0x0806, hardware type 1 and protocol type 0x0800. Learn sender IP/MAC pairs from valid incoming ARP frames. Reply to opcode 1 requests whose target IP equals local_ip with opcode 2; reply to opcode 8 InARP requests whose target MAC equals local_mac with opcode 9. Replies address the incoming Ethernet source and sender ARP addresses. Other traffic does not trigger replies.
- An accepted IP lookup returns a cached MAC or broadcasts requests for resolution. 0xffffffff and directed local-subnet broadcasts resolve to ff:ff:ff:ff:ff:ff without a network query. The pinned design tests subnet membership against gateway_ip using subnet_mask; addresses outside that subnet resolve gateway_ip. REQUEST_RETRY_COUNT includes the first transmission; subsequent attempts use REQUEST_RETRY_INTERVAL, followed by REQUEST_TIMEOUT after the last retry. Successful lookup reports error=0; exhausted retries report error=1. Request packets use opcode1, local sender addresses, zero target hardware address and broadcast Ethernet destination.
- Qualification drives arp_response_ready continuously high. The pinned top clears response MAC/error on idle cycles even while a prior response valid is stalled, so sustained backpressure on this lookup-response interface is outside the qualified envelope. Ethernet frame interfaces are still tested with backpressure. This upstream limitation is disclosed, not silently required as a desirable protocol behavior.
- arp_cache is a direct-mapped hash cache, not an LRU replacement cache despite a stale README file-list label. It stores full IP tags and MAC values; a hash collision replaces the previous entry and a mismatched tag reports a miss. Reset/clear invalidates entries through a sweep; wait for query/write ready. Its lfsr helper is the original parameterized combinational parallel LFSR/CRC transform. Preserve parameter declarations and the documented Galois/Fibonacci/feed-forward/reverse behavior used by this closure.
- Preserve both 8-bit and 64-bit Ethernet datapaths used by the whole upstream benches. All eleven usable benches are separate equally weighted points: four cocotb and seven MyHDL benches. Multiple vectors inside a bench do not add cases or points. This is finite simulation qualification, not exhaustive equivalence.

Curator provenance: the original README and substantial original frame/LFSR documentation are retained unchanged; routing, reset, cache and retry clarifications above were checked against pinned RTL. Simulation-only parameter diagnostics are removed from normalized golden RTL, with exact original blocks retained privately. Submit all declared files; no simulator file/network/process I/O, external includes, delays or force/release are permitted. Synthesizable initialization and constant elaboration helpers are permitted. No golden implementation is included in the public input.
'''
