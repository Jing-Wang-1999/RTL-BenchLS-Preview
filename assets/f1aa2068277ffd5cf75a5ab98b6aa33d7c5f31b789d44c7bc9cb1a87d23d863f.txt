# usbfs_transaction: default-configuration specification

Implement the module interface below. All arithmetic is fixed-width unsigned unless explicitly stated. Sequential updates use pre-edge values and occur on the stated clock edge. Preserve externally observable cycle timing, including outputs outside valid transactions wherever defined. No golden RTL is provided to the implementation model.

## Scope and clocks

A USB packet-to-endpoint transaction controller. Sole rising `clk`, asynchronous low `rstn`. Default descriptors are all zero, EP00 and EP81..84 packet limits32 bytes, and all isochronous flags0. These defaults leave useful packet routing and custom EP00 responses active; they are not a complete enumerable USB device. This module does not verify CRC, device address, endpoint-descriptor consistency or retry replay. Upstream supplies packet PID/endpoint and `rp_fin/rp_okay`.

Reset clears all public registered outputs, TX count, remembered endpoint, EP00 setup flag/remaining length, all data-toggle bits, and response index. The EP00 response-byte pipeline has no reset: it updates each clock from command/index even during reset. Do not require its initial declaration value after arbitrary reset assertion; externally transmitted bytes become defined through this pipeline.

PIDs use nibble encodings OUT1, IN9, SETUPD, SOF5, DATA03, DATA1B, ACK2, NAKA. `tp_sta` is a one-cycle packet-start pulse; `tp_pid` otherwise holds. `tp_byte_req` requests one response decision: on its rising-clock observation `tp_fin_n` becomes1 and byte updates if data remains and the selected source is valid; otherwise fin_n becomes0 and byte holds. Between requests fin_n and byte hold. `tp_cnt` counts remaining bytes. There is no automatic retry buffer.

## Completed packet actions

Only `rp_fin && rp_okay` triggers packet-level actions. SETUP remembers endpoint; for endpoint0 set setup flag and data toggle1. OUT remembers endpoint; endpoint0 clears setup flag. IN remembers endpoint, emits start and defaults to NAK/count0. For endpoint0 it clears setup flag and emits its selected DATA0/1, taking min(remaining length,32) and deducting that amount immediately. For endpoints1..4, if corresponding input valid is1, emit its selected DATA0/1 and count32; otherwise retain NAK. Other endpoints NAK.

ACK toggles the remembered endpoint's DATA toggle for endpoints0..4. There is no additional test that the ACK follows a particular pending packet. DATA0 or DATA1 completion always emits ACK at defaults. If remembered endpoint0, clear remaining length; when setup flag is1, replace it with setup command wLength if its direction bit7 is1, otherwise zero, and reset response index. Data packet completion does not clear setup flag. Unsupported PIDs have no packet-level effect.

After those packet actions, a simultaneous byte request uses the *old* remembered endpoint, count, source-valid and source-data. Its assignments to count and response-index have priority over earlier assignments on that edge when data is available. Thus simultaneous packet-completion and byte requests are deterministic but do not use the newly selected endpoint.

## Endpoint streams and setup command

Endpoint81..84 input ready is combinational `tp_byte_req && old_count!=0 && remembered_endpoint==1..4`, independent of source valid. A requested valid byte is captured, count decremented, and fin_n set. EP00 is always a valid source; requested bytes increment a 9-bit response index modulo512. A source that becomes invalid early terminates the current byte response (fin_n0) without clearing count.

Every clock, OUT endpoint1..4 data/valid default to0. If `rp_byte_en`, route the byte by remembered endpoint and assert that endpoint's valid for one clock. These byte deliveries are **not gated by PID, packet completion, rp_okay or DATA toggle**; they are speculative streaming bytes and CRC acceptance/deduplication is not performed here. At endpoint0, while setup flag is1, each enabled byte shifts `{rp_byte,old_setup[63:8]}`. After eight little-endian setup bytes the command layout is bmRequestType7:0, bRequest15:8, wValue31:16, wIndex47:32, wLength63:48.

## EP00 response pipeline

On every rising clock compute an 8-bit EP00 byte from old command and old response index. Byte requests consume the previous pipeline value. Thus adjacent requests can repeat the first byte when index just changed; preserve the registered lookup latency. Standard recognized command patterns in low32 bits are:

| Low32 pattern, X is ignored bits | Response at index i |
|---|---|
| XXXX0880 | 01 at i=0, otherwise00 |
| 01XX0680 | Device descriptor byte i, zero when i>=18; all zero by default |
| 02XX0680 | Configuration descriptor byte i (512-byte array, all zero default) |
| 03000680 | Bytes04,03,09,04 then00 |
| 03010680 through03060680 | String1..6 byte i, zero when i>=64; all zero default |
| Other | `ep00_resp` sampled every clock |

Descriptor arrays are traversed most-significant byte first. Full formal qualification uses binary inputs; casex patterns denote only ignored command fields, not a promise about X propagation.

On valid packet completion, `sof` pulses for PID SOF. `sot` pulses for endpoint0 SETUP, or nonzero-endpoint IN/OUT. They are zero every other cycle. No optional parameter configurations are qualified by this case. Out-of-range endpoint source-array access has no valid-byte guarantee; endpoint controls and NAK behavior above still apply.
