# Programmable timer — rtlpp_10999

Implement module `rtlpp_10999`. There are no parameters. Inputs are `clk`, `reset_n`, `chipselect`, `write_n` (one bit each), `address[2:0]`, and `writedata[15:0]`. Outputs are `irq` (one bit) and registered `readdata[15:0]`.

All state updates on the rising edge of `clk`. `reset_n` is an asynchronous active-low reset. Reset initializes the 32-bit counter and period to 49,999 (0x0000C34F); the running flag, four-bit control register, timeout flag, previous-zero flag, reload-pending flag, 32-bit snapshot and readdata are zero. No pre-reset power-up state is promised.

A write is accepted on an edge exactly when chipselect is high and write_n is low. Address is a register index, not a byte address.

| Address | Read value (zero-extended to 16 bits) | Write effect |
|---|---|---|
| 0 | bit 1 running; bit 0 timeout; other bits zero | Clear timeout, regardless of write data |
| 1 | Stored control bits 3:0 | Store writedata[3:0]; bit 2 issues start and bit 3 issues stop |
| 2 | Period bits 15:0 | Replace low half and schedule a reload on the next edge |
| 3 | Period bits 31:16 | Replace high half and schedule a reload on the next edge |
| 4 | Snapshot bits 15:0 | Capture the current counter into the entire snapshot |
| 5 | Snapshot bits 31:16 | Capture the current counter into the entire snapshot |
| 6–7 | Zero | None |

Every non-reset clock edge samples the addressed read value into readdata, even if chipselect is low or a write is occurring. Reads on a simultaneous write report the pre-edge value. Snapshot captures also use the pre-edge counter.

Control bit 0 enables interrupts, bit 1 selects continuous mode. Bits 2 and 3 remain readable stored bits, but start and stop act only on the control-write edge; stored ones do not continuously retrigger commands. `irq` is combinationally the timeout flag AND stored control bit 0.

The following rules all use pre-edge state and apply simultaneously. They specify boundary-cycle behavior and priorities:

* The reload-pending flag becomes whether this edge accepts a period-half write. Thus period writes reload one edge later, using the then-current combined period. Consecutive half writes can cause consecutive reloads.
* If running or reload-pending, the counter loads the period if the counter is zero or reload-pending; otherwise it decrements modulo 2^32. If neither, it holds. Starting does not itself load or decrement a previously stopped counter. A stop edge can still decrement or reload when the old running flag was one.
* An accepted start command sets running, with priority over every stop condition, including simultaneous start and stop bits. Otherwise an accepted stop command, reload-pending, or (counter zero AND continuous mode off) clears running. Otherwise running holds. On a control write, the zero/continuous decision uses the old control bit.
* The previous-zero flag samples whether the counter is zero on every edge, including while stopped. A timeout event occurs when the current counter is zero and previous-zero is false; it does not require running. An accepted status write clears timeout with priority over setting it on that event. Otherwise timeout remains sticky.

In one-shot mode, a zero counter that is still running reloads the period on the same edge that stops it. A zero period is legal; the edge detector prevents a continuously zero counter from producing a new timeout event every cycle. There is no read strobe, waitrequest, clock enable input, or automatic snapshot on read.
