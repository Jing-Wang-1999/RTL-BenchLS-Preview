# tiny-gpu complete project
Implement gpu and the eleven other required modules using the unchanged original README and its architecture/ISA figures under specification/original/. The original document defines the educational GPU architecture, eleven-instruction ISA, per-thread registers, scheduler, memory controllers, and kernel-launch procedure. This case is one complete GPU project, not separate cases for each kernel.

Curator configuration and interface clarification from the pinned release:
- Freeze the declared default configuration: two compute cores, four threads per block, eight-bit data/address, sixteen-bit instructions, four data-memory channels and one program-memory channel. All state uses rising clk and synchronous active-high reset. Before launch, reset, load external memories, write the eight-bit thread_count via device_control_write_enable, then hold start high until done. A new launch requires reset; this release is not a back-to-back kernel command queue. done clears on reset and asserts once all dispatched blocks have completed. The finite qualified kernels use positive thread counts 4 and 8; overflow in the eight-bit block-count calculation and zero-thread launches are outside the envelope.
- Each external memory channel presents valid plus address (and write data). Memory acknowledges a pending request with ready; read data is valid with read-ready. Maintain a request until accepted. Data/program memories are distinct address spaces, with one-byte data and one sixteen-bit instruction per address. No byte-enable or AXI burst protocol exists. The original fixture supplies memory responses through these public ports, with result validation in external memory after done.
- Instruction [15:12] opcodes: 0 NOP, 1 BRnzp, 2 CMP, 3 ADD, 4 SUB, 5 MUL, 6 DIV, 7 LDR, 8 STR, 9 CONST, f RET. For arithmetic, rd=[11:8], rs=[7:4], rt=[3:0]. LDR loads rd from memory[rs]; STR stores rt to memory[rs]. CONST writes immediate[7:0]. Branch uses mask[11:9] and absolute instruction address immediate[7:0]. Ordinary next PC increments by one. Eight-bit arithmetic truncates to eight bits, division is unsigned integer division with nonzero divisor; zero divisor is outside this case.
- R0..R12 are writable per-thread registers, initialized to zero; R13/R14/R15 are read-only block index, block dimension and thread index. Thread count and block IDs govern work allocation. Inactive threads in a partial block must not generate effects. Threads within a block converge to one PC after each instruction; divergent branches, cache, warp scheduling and overlapped instruction pipelines are not part of this version. The README's Cache section is explicitly WIP: no cache module is in the selected closure.
- Material ISA limitation: the original ISA figure describes CMP as signed ordering of rs-rt, but the pinned ALU compares unsigned expressions and packs the relation flags inconsistently with that prose. Equality comparison and BRz are the qualified, portable subset used by the upstream kernels. Non-equality ordered CMP branches are outside this frozen contract; do not treat the golden implementation as proof of signed-comparison support. This limitation is explicit and the golden RTL is unchanged.
- Required helper roles: dcr captures thread count; dispatch schedules blocks and completion; controller arbitrates/throttles asynchronous memory channels; core integrates scheduler/fetcher/decoder and per-thread units; fetcher obtains sixteen-bit instructions; decoder implements the supplied ISA; scheduler runs fetch/decode/request/wait/execute/update to completion; registers/alu/lsu/pc supply the thread datapath and next-PC logic. Module ports and parameter defaults are in interfaces/modules.v. Generated implementations may use different internal names and state encodings provided the declared modules are present and the public GPU behavior is correct.

Both original kernel benches are retained: matrix addition and matrix multiplication. Each is one Boolean point with all original final-memory assertions; vectors/elements are not extra cases. Only optional diagnostic format_cycle traversal of DUT internals is disabled in the private helper, so no internal signal hierarchy is required by evaluation. The unchanged memory driver, setup, programs and score assertions remain private. The supplied README itself contains illustrative assembly kernels. Finite kernel tests do not establish exhaustive ISA correctness.
