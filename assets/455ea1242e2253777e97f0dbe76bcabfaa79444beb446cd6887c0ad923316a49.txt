## Observed Behavior
<!--
Please describe the problem you saw. Include waveforms (in VCD or Verilator/GtkWave FST format only please) and log files if possible.
-->
After https://github.com/lowRISC/ibex/commit/169785d0711335c94561a93146e069766eec138c commit the "ibex_simple_system" and UVM tests cannot be compiled because of the error:

`ALOG: Error: VCP2675 /ibex/build/lowrisc_ibex_ibex_simple_system_0/src/lowrisc_ibex_ibex_top_0.1/rtl/ibex_register_file_fpga.sv : (63, 1): Cannot write to a variable 'mem[k]' that is also driven by an always_comb/always_latch/always_ff procedural block. `


The problem is caused by wrong SV code:
https://github.com/lowRISC/ibex/blob/c78acac8cc381293900f3648e365ddd136784789/rtl/ibex_register_file_fpga.sv#L54-L65

In this case the mem[] variable is written in always_ff  and initial block what is prohibited by SV LRM:

> "The always_ff procedure imposes the restriction that it contains one and only one event control and no
> blocking timing controls. Variables on the left-hand side of assignments within an always_ff procedure,
> including variables from the contents of a called function, shall not be written to by any other process."

## Expected Behavior
<!-- Please describe the behavior you expected to see instead. -->

The code should compile without errors.
