# [rom_ctrl, dv] Uncovered conditional coverage in tlul_adapter_reg.sv

Hi,

According to 2nd oct nightly regression coverage dashboard [here](https://reports.opentitan.org/hw/ip/rom_ctrl_64kB/dv/latest/cov_report/mod64.html#Cond) stating that a conditional coverage for [L208](https://github.com/lowRISC/opentitan/blob/29d22a60a272d26f8987bc39fa4ba0794f02a0e8/hw/ip/tlul/rtl/tlul_adapter_reg.sv#L208C72-L208C83) in tlul_adapter_reg.sv is uncovered. The tool never seen 0, 0, 0, 1, 0 and 0, 1, 0, 0, 0 transitions. That makes sense as **malformed_meta_err**, **tl_err** and **instr_error**  are dependent over instruction type being invalid. Which corresponds that if there is a malformed_meta_err there would be a  **tl_err** and **instr_error**. Hence, 01000 is a non-occuring case.
```             <Non-ocurring case> [tlul_adapter_reg.sv L208]
| addr_align_err | malformed_meta_err | tl_err | instr_error | intg_error
|  ------------- |  ----------------- |  ----- | ----------- | ---------
|        0       |          1         |   0    |      0      |     0
```
Regarding the next case: 
```             <uncovered case> [tlul_adapter_reg.sv L208]
| addr_align_err | malformed_meta_err | tl_err | instr_error | intg_error
|  ------------- |  ----------------- |  ----- | ----------- | ---------
|        0       |          0         |   0    |      1      |     0
```
This could only be occuring if instruction type is valid and instruction fetch is disabled and tl_i.a_opcode is **GET**
