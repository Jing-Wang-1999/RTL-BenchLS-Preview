# 64-bit Ethernet ARP header receiver

Implement `rtlpp_03744`, with no parameters. All state advances on rising `clk`; `rst` is synchronous active-high.

| Inputs | Width |
|---|---:|
| clk, rst, s_eth_hdr_valid, s_eth_payload_axis_tvalid, s_eth_payload_axis_tlast, s_eth_payload_axis_tuser, m_frame_ready | 1 each |
| s_eth_dest_mac, s_eth_src_mac | 48 each |
| s_eth_type | 16 |
| s_eth_payload_axis_tdata | 64 |
| s_eth_payload_axis_tkeep | 8 |

| Outputs | Width |
|---|---:|
| s_eth_hdr_ready, s_eth_payload_axis_tready, m_frame_valid, busy, error_header_early_termination, error_invalid_header | 1 each |
| m_eth_dest_mac, m_eth_src_mac, m_arp_sha, m_arp_tha | 48 each |
| m_eth_type, m_arp_htype, m_arp_ptype, m_arp_oper | 16 each |
| m_arp_hlen, m_arp_plen | 8 each |
| m_arp_spa, m_arp_tpa | 32 each |

Maintain IDLE, READ_HEADER and WAIT_LAST states, a beat pointer initially zero, registered ready/valid and pulse outputs, and retained field registers. In the descriptions below all decisions use pre-edge values; omitted fields hold. On each nonreset edge first clear both error pulses, set header-ready and payload-ready to zero unless specified below, and retain frame-valid only when its previous value is one and `m_frame_ready=0`; call that tentative retained-valid V.

In IDLE reset the beat pointer to zero and set next header-ready to !V. A handshake using the **old registered** `s_eth_hdr_ready && s_eth_hdr_valid` captures all three Ethernet header fields, enters READ_HEADER, drives next header-ready=0 and payload-ready=1. Otherwise remain IDLE. No Ethernet-type filtering occurs.

In READ_HEADER keep payload-ready=1. A cycle with payload-valid=1 consumes the beat and increments the eight-bit pointer; payload-ready is already asserted throughout this state. Capture the pointer-selected ARP fields below. After pointer 3 enter WAIT_LAST unless the same beat ends the frame. If that beat has `tlast=1`, terminate directly to IDLE, set next payload-ready=0, and apply this ordered check: if pointer !=3 OR `(tkeep & 0x0f)!=0x0f`, pulse early-termination; else if previously captured hlen !=6 OR plen !=4, pulse invalid-header; otherwise set frame-valid to !tuser. Then set next header-ready to the inverse of resulting frame-valid. On errors V is retained rather than newly asserted. With no payload-valid remain in READ_HEADER and hold pointer/fields.

In WAIT_LAST keep payload-ready=1 and discard payload data. On a valid last beat, check hlen/plen and then final tuser as above (no tkeep or pointer test), return IDLE, next payload-ready=0, and next header-ready inverse to resulting frame-valid. Otherwise remain WAIT_LAST. Earlier payload-user bits are ignored; only the terminating beat's user bit suppresses a frame. Keep bits on the first three beats, and on nonfinal beat 3, do not gate field capture. The receiver therefore does not promise to reject every malformed byte-valid pattern.

Number payload bytes in each beat from lane 0 (`tdata[7:0]`) through lane 7 (`tdata[63:56]`); byte 0 of a multi-byte network field is its most significant byte:

| Beat pointer | Byte-to-field mapping |
|---|---|
| 0 | htype=lanes 0,1; ptype=2,3; hlen=4; plen=5; oper=6,7 |
| 1 | sha=lanes 0..5; spa[31:16]=lanes 6,7 |
| 2 | spa[15:0]=lanes 0,1; tha=lanes 2..7 |
| 3 | tpa=lanes 0..3; lanes 4..7 ignored |

All captured fields are exposed immediately after their capture edge, including fields of subsequently rejected frames. `m_frame_valid` remains asserted until accepted. Admission of a new header is blocked while a completed frame remains pending. `busy` is registered from the next FSM state, so it asserts on header capture and clears on frame termination, even if a valid completed frame remains pending.

Reset forces IDLE, pointer=0, payload-ready=0, frame-valid=0, busy=0 and both error pulses=0. **Header-ready is not reset:** it retains its prior value during reset and is refreshed on the first subsequent IDLE edge. Field registers are not reset; their storage enables are computed from the old state and inputs even on reset edges, so such an edge may still capture fields. Initial declarations in the source initialize controls and fields to zero at simulation powerup, but this reset-based task does not require immediate powerup field values before capture; valid-frame data is fully captured before presentation. The non-reset header-ready behavior after an in-flight reset is defined as above, not forced to zero. All listed edge cases must remain representable without additional traffic assumptions.
