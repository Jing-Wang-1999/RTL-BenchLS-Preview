# UART command to AXI4 project
Implement the three-module uart2axi4 project using the unchanged bilingual original README in specification/project.md. The Chinese section 3.5 contains the complete original ASCII command grammar; both language sections are part of the input. The original document covers UART streams, buffering, byte ordering, framing and command/response behavior.

Curator clarification of the pinned configuration and documentation defects:
- uart2axi4 instantiates uart_rx and uart_tx; implement all three declared files. Clock edges are rising, reset rstn is asynchronous active-low and must be asserted initially. Standalone UART defaults remain available. Qualified whole-project configuration uses CLK_FREQ=16000000, BAUD_RATE=115200, PARITY="NONE", BYTE_WIDTH=4 and A_WIDTH=32. The second upstream bench uses 4 MHz TX / 5 MHz RX, 115200 baud, odd parity, one stop bit, a two-byte TX stream with FIFO_EA=0, and RX FIFO_EA=1.
- UART transmits start-low, eight bits LSB first, the selected parity, then STOP_BITS high stop bits. Fractional division distributes clock periods as described by the original manual. TX transmits enabled bytes least-significant byte first. All i_tkeep bits are active-high; the Chinese sentence saying i_tkeep[0]=0 selects a byte is a typo (the English section is correct). With no RX FIFO, valid is a one-cycle arrival pulse and cannot wait for ready; with buffering, unread data is held and a full queue drops a new byte, pulsing overflow.
- Commands accept either letter case for W/R and hexadecimal digits. Spaces separate words. CR or LF terminates a command; ignored leading whitespace/empty newline does not create an operation. W<address> <data>... issues one write burst; R<address> <length> issues one read burst. Use the documented legal range 1..256 words, address/data widths from the declaration, and no commands overlapping an in-progress transaction. AXI LEN is the number of beats minus one. Write data is ordered exactly as the command; LAST accompanies its final beat. Address and data valid/ready handshakes determine acceptance. BREADY is permanently high. Read ends on the requested beat count or RLAST, whichever arrives first. No WSTRB, IDs or response-status ports exist in this simplified interface.
- For BYTE_WIDTH=4, successful writes return the eight-character word "okay    ", followed by an extra space and LF; invalid commands return "invalid ", followed by an extra space and LF. Read data is lowercase fixed-width hexadecimal, eight characters per word, separated by spaces; a trailing space precedes the final LF. Other documented BYTE_WIDTH values truncate/pad these fixed little-endian response words to 2*BYTE_WIDTH characters. Exact response formatting is a curator clarification of the original prose's okay/invalid examples.
- The public contract requires initial reset. Reference-only initial assignments duplicating reset values and the parameter diagnostic printing section are removed; every original file is retained. No functional state transition or data equation is changed. This case excludes malformed numeric overflow and traffic exceeding UART reply-buffer capacity, whose behavior is not fully specified upstream.

Scoring uses both original benches, with explicit failure assertions, response checks and added observation of public AXI address/data ports. One bench is one point; configurations and vectors do not increase the case count. Finite verification is not exhaustive protocol proof.
