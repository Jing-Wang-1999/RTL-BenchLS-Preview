# Single-precision floating-point adder

Implement module `adder`: one outstanding IEEE-754 binary32 addition, with separately handshaken operands and a backpressured result. All sequential behavior uses the rising edge of `clk`. There is no combinational bypass or overlap between transactions.

## Interface

| Direction | Port | Width | Meaning |
|---|---|---:|---|
| Input | `clk`, `rst` | 1 each | Clock; synchronous active-high reset |
| Input | `input_a`, `input_b` | 32 each | Binary32 operand bit patterns |
| Input | `input_a_stb`, `input_b_stb` | 1 each | Operand valid strobes |
| Output | `input_a_ack`, `input_b_ack` | 1 each | Registered operand ready signals |
| Output | `output_z` | 32 | Registered result bit pattern |
| Output | `output_z_stb` | 1 | Registered result valid |
| Input | `output_z_ack` | 1 | Result ready |

The original interface also exposes state-encoding parameters `get_a=0`, `get_b=1`, `unpack=2`, `special_cases=3`, `align=4`, `add_0=5`, `add_1=6`, `normalise_1=7`, `normalise_2=8`, `round=9`, `pack=10`, and `put_z=11`, each four bits. Evaluation uses these defaults; there are no configurable data widths or rounding modes.

## Handshake and reset

A transfer occurs on an edge with the corresponding strobe and acknowledgment already high immediately before the edge. Acknowledgments are not combinational responses to strobes.

After a reset edge, both input acknowledgments and result valid are zero, and the next transaction waits for A. On the first non-reset edge, A acknowledgment rises. Accepting A lowers its acknowledgment. B acknowledgment rises on the following edge and B can first be accepted on the edge after that. B presented earlier is ignored. Accepting B lowers B acknowledgment; neither input is accepted while computing or awaiting result consumption.

Result valid first rises when computation finishes, regardless of `output_z_ack`. A ready signal already high at that edge does not consume the newly asserted result. Consumption can occur from the next edge onward. The result and valid remain stable while valid is high and acknowledgment is low. Consumption lowers valid; A acknowledgment rises one edge later, allowing A acceptance another edge later. Outside computation completion, `output_z` retains the previous result, including after consumption.

Reset has priority over state/handshake progress and abandons the outstanding transaction. It does not initialize the result-data register. The result-data register may still be updated on a reset edge that coincides with result presentation from the interrupted transaction; while result valid is zero, its data is not a valid transaction. No defined power-on state exists before a reset edge. Operands must remain stable through their acceptance edge.

## Arithmetic

For finite inputs, calculate addition with round-to-nearest, ties-to-even. Support normal numbers and gradual underflow/subnormal inputs and outputs. Overflow returns signed infinity. Exact cancellation of nonzero finite operands returns positive zero. There are no exception-flag outputs, alternate rounding modes, saturation mode, or flushing of subnormals.

Apply the following special cases in priority order:

| Inputs | Result bits |
|---|---|
| Either operand is any NaN, including signaling NaN | `32'hffc00000` |
| A and B are opposite-signed infinities | Quiet NaN with B's sign, exponent `8'hff`, fraction `23'h400000` |
| A is infinity, including same-signed infinities | A's signed infinity |
| B is infinity | B's signed infinity |
| Both operands are signed zeros | Zero with sign `A.sign AND B.sign` |
| Only A is zero | B unchanged |
| Only B is zero | A unchanged |

NaN payloads are not propagated. In particular `+Inf + -Inf` yields `ffc00000`, whereas `-Inf + +Inf` yields `7fc00000`.

## Observable computation timing

Let B acceptance be edge 0. Every special-case result above is presented with valid high at edge 3. Other finite nonzero operations first present their result at edge `10 + D + N`.

`D` is the absolute difference of operand effective exponents: an exponent field of zero has effective exponent -126; otherwise subtract 127 from the exponent field. `N` is the number of left-normalization positions needed by the unrounded result significand, including its next two low-order rounding bits, limited by the minimum exponent -126. The provisional exponent is the larger effective exponent, plus one if same-sign significand addition carries into the next position. A nonzero provisional significand needs one position per leading zero, counting into those two additional rounding positions if the 24 primary bits are zero; an exactly zero value including those positions consumes all available exponent positions down to -126. The unrounded significand includes the effect of operand alignment with discarded low bits accumulated for rounding; normalization draws in the two next rounding bits. This timing requirement includes long cancellation and exponent-difference paths and must not be replaced by a fixed-latency or combinational adder.

Examples, assuming continuously asserted output acknowledgment: `1.0 + 1.0` first asserts valid 10 edges after B acceptance; `1.0 + 0.5` takes 11; `1.0 + (-1.0)` takes 136; any zero shortcut takes 3. Result valid is consumed on the following edge at the earliest.
