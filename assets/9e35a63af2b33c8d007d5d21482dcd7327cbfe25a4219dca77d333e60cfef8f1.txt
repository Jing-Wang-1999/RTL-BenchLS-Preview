## Exact pass-through behavior

This is a simplified registered pass-through with nonstandard AXI handshakes,
not a fully AXI-compliant bridge. Reset is synchronous active-low on aclk and
clears every output register. Master response-ready outputs m_axi_bready and
m_axi_rready remain zero after reset; mi_w_error and mi_r_error are always zero.
Do not add response-ready forwarding, buffering, or control storage.

Each address channel independently captures the slave address/protection,
asserts slave ready and master valid on an edge with slave valid and PREVIOUS
slave ready low. Otherwise, if master ready is high, clear both flags; otherwise
hold all channel registers. The capture has priority even if master ready is high.
The write-data channel follows the same rule, capturing data and strobes.
Master bvalid with previous slave bvalid low captures bresp and asserts slave
bvalid; otherwise slave bready clears slave bvalid. Read responses use the same
priority with rvalid/rready, capturing rdata and rresp. Captured payloads hold
until the next capture, including cycles when valid is low.

Control address and data ready outputs are independent toggling acknowledgments:
each next ready is its corresponding input valid AND NOT its previous ready.
Control write response valid becomes input bready AND NOT its previous bvalid;
its response is always OKAY. This is independent of control address/data receipt.
Control read valid is asserted when its previous value is low and previous
control arready is high; otherwise input rready clears it, otherwise it holds.
Control read data and response are always zero after reset. Control addresses,
write data and strobes do not affect any stored data.

Widths: main addresses 16, main protection 3, main data 32, main strobes 4,
main responses 2; control addresses 12, control data 32, control strobes 4,
control responses 2. All valid/ready, clock, reset and error ports are one bit.
