# Three-stage floating-point add/subtract preparation

Implement `rtlpp_04539`, a predecoded binary32 add/subtract datapath that produces an unrounded intermediate result. Inputs: scalar `clk`,`rst`,`flush_i`,`adv_i`,`start_i`,`is_sub_i`,`signa_i`,`infa_i`,`signb_i`,`infb_i`,`snan_i`,`qnan_i`,`anan_sign_i`,`addsub_agtb_i`,`addsub_aeqb_i`; `exp10a_i[9:0]`,`exp10b_i[9:0]`,`fract24a_i[23:0]`,`fract24b_i[23:0]`. Outputs: scalar `add_rdy_o`,`add_sign_o`,`add_sub_0_o`,`add_shr_o`,`add_inv_o`,`add_inf_o`,`add_snan_o`,`add_qnan_o`,`add_anan_sign_o`; `add_shl_o[4:0]`,`add_exp10sh0_o[9:0]`,`add_fract28_o[27:0]`.

Three register stages advance together only on rising clk with adv_i1. Each stage uses old values, so an input sampled at edge1 reaches outputs after the third advancing edge. No data register is reset or flushed; they retain old values while stalled and are initially unspecified. Ready shifts start_i through the same three advancing stages. Active-high asynchronous rst clears all three ready bits; otherwise flush_i clears them synchronously even when adv_i0. Reset/flush do not suppress advancing data updates. When ready is0, data still follows the stated register recurrences; it must not be forced zero.

Stage1 selects A as unshifted operand if addsub_agtb_i1, else B; the other operand is shifted. These comparison inputs are consumed as given, not recomputed or constrained. Effective signs are signa_i and signb_i XOR is_sub_i; subtract flag is their XOR and result sign is the selected unshifted operand's sign. The10-bit modular selected exponent difference is saturated to31 if any bits9:5 are1, otherwise its low5 bits are used. If either infinity flag is1, force shift count0 and both stored fractions0. Store selected exponent, equality input, and metadata: invalid=infa_i AND infb_i AND effective-sign difference, infinity=infa_i OR infb_i; snan,qnan,anan_sign pass through unchanged.

Stage2: append two zeros to the stored shifted24-bit fraction and shift the26-bit vector right by the5-bit shift count. Sticky is0 for shifts0–2, OR of original fraction bits[shift−3:0] for shifts3–25, and OR of all24 bits for shifts26–31. Form28-bit shifted vector {0,shifted26,sticky} and28-bit unshifted vector {0,unshifted24,000}. Add these for addition or subtract shifted from unshifted for subtraction, modulo2^28. Store result bits27:1 as27-bit fraction, plus sticky separately; store sub_zero=(stored equality AND subtract), sign/exponent and all metadata.

Stage3: propagate metadata to corresponding add_* outputs, sign to add_sign_o, sub_zero to add_sub_0_o, and exponent unchanged to add_exp10sh0_o. add_fract28_o={stage2 fraction27,sticky}, add_shr_o=fraction27[26]. Count leading zeros relative to bit25: if highest set bit is26 or25 the count is0; highest bit24 gives1 down to bit0 gives25; allzero gives0. add_shl_o is0 when this count0, sub_zero1 or exponent1. Otherwise use count if unsigned exponent>count; count−1 if equal; else exponent[4:0]−1 modulo32. It supplies a recommended shift but does not apply it or update exponent. No rounding or full floating-point result packing occurs. All arithmetic and out-of-domain predecode input combinations obey these fixed-width recurrences, without invented magnitude-consistency assumptions.
