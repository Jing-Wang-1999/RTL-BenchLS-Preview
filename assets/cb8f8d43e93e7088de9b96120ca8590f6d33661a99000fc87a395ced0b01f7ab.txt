# rtlpp_08931

This synchronous token controller has parameter `COUNTER_Width = 6`. Inputs are one-bit `clk`, active-low asynchronous reset `rst_n`, `start_token`, `end_token`, `trigger`, and `reStart`. Outputs `enable_start_out` and `enable_end_out` are one bit. Both internal outstanding counters are `[COUNTER_Width:0]`, or 7 bits at the default.

The four states are Idle, Reset, Filter, and Bypass. Asynchronous reset clears both counters and both enables and puts the state in Idle. Otherwise state changes on rising edges: Reset goes to Idle; Idle goes to Filter if `trigger=1`, otherwise stays Idle; Filter goes to Reset if `trigger=0`, to Bypass if `trigger=1` and `outstanding_r=0`, and otherwise remains Filter; Bypass remains there while `trigger=1` and goes to Reset when it is 0. Invalid state selects Reset.

On every rising edge, the registered enables are computed from the next state: Filter sets start-enable to `start_token` and end-enable to 0; Bypass sets them to `start_token` and `end_token`; Idle, Reset, and invalid states clear both. Outputs continuously mirror these registers.

`reStart` synchronously clears both counters without directly changing state or enables. Otherwise `outstanding_c` increments for start-only, decrements for end-only, and holds when tokens are equal. `outstanding_r` captures `outstanding_in`. Combinational `outstanding_in` is zero when next state is Reset or Bypass; in Idle it applies the same start/end update to `outstanding_c`; in Filter it decrements `outstanding_r` on any `end_token` and otherwise holds it. Arithmetic wraps modulo `2^(COUNTER_Width+1)`, including decrement at zero. There are no submodules.
