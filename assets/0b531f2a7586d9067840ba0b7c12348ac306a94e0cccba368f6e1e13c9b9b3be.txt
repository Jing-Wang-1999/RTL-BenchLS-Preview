# uart_rx: default-configuration specification

Implement the module interface below. All arithmetic is fixed-width unsigned unless explicitly stated. Sequential updates use pre-edge values and occur on the stated clock edge. Preserve externally observable cycle timing, including outputs outside valid transactions wherever defined. No golden RTL is provided to the implementation model.

## Interface

```verilog
module uart_rx (
    input  wire        clk_i,
    input  wire        rstn_i,
    input  wire        rx_i,
    input  wire [15:0] cfg_div_i,
    input  wire        cfg_en_i,
    input  wire        cfg_parity_en_i,
    input  wire [1:0]  cfg_parity_sel_i,
    input  wire [1:0]  cfg_bits_i,
    
    output wire        busy_o,
    output reg         err_o,
    input  wire        err_clr_i,
    output wire [7:0]  rx_data_o,
    output reg         rx_valid_o,
    input  wire        rx_ready_i
);
endmodule
```

## Function and clock/reset

Receive an asynchronous serial character, least-significant bit first. `clk_i` is the sole rising-edge clock; `rstn_i=0` asynchronously resets the receiver. Reset sets the state idle, receive data FF, bit counter zero, parity accumulator zero, input synchronizer 111, baud count and completion flag zero, and sticky error zero. `busy_o` is high in every state except idle. There are no parameters.

`cfg_bits_i` 0,1,2,3 selects 5,6,7,8 data bits; unused high result bits are zeroed on each data sample. `cfg_div_i` is the full-bit terminal count, so ordinary timer periods contain divisor+1 clocks. Half-start terminal count is floor(divisor/2). This is a cycle model; no minimum divisor, framing-error detector or oversampling majority vote is implemented. `cfg_en_i=0` forces state idle and synchronizer 111 on the next clock; it does not independently reset data, bit index or error. Disabling midcharacter can therefore preserve a partial bit index into the next frame. Configuration inputs are live, not latched.

## Receive timing

The synchronizer shifts `{old[1:0],rx_i}` while enabled. A start trigger is old synchronizer bit2 high and bit1 low. Samples use bit2. In idle a detected falling edge enters start and enables the half-bit timer immediately. In start, the parity next value is zero and the timer remains enabled in half-bit mode. A previously registered completion flag advances to data; the start bit is not rechecked for being low.

The timer runs when idle detects a start or in start, data, save, parity or stop. On each enabled edge it compares its old count with the applicable terminal count; equality clears the counter and sets its registered completion flag, otherwise increments modulo 65536 and clears that flag. Disabled timer clears both. State and data logic consume the old completion flag, one clock after the equality is registered.

In data, each completion shifts the synchronized input into the most significant position of the selected character width and increments a 3-bit bit index. When the old index equals 4,5,6,7 for the selected width, reset that index to zero and enter save. The parity accumulator XORs each sampled data bit. Data holds on all nonsampling clocks.

In save, assert combinational `rx_valid_o` continuously and keep `rx_data_o` equal to the stored character until `rx_ready_i`. The timer continues running during this wait. Ready advances to parity if enabled, otherwise stop. There is no receive queue and no automatic physical-line pause; a late ready can miss subsequent serial timing. This ready behavior must be reproduced, without assuming ready is always asserted. The valid character is offered before parity and stop processing.

In parity, wait for the next completion and compare synchronized input with the required parity bit: selector0 is complement of data XOR (odd), selector1 is data XOR (even), selector2 constant0, selector3 constant1. A mismatch sets `err_o`; then enter stop. Stop waits for the next completion and returns idle, regardless of line level. `err_clr_i` has priority over setting the sticky error on the same edge. Parity accumulator updates on every completion in every state using the state's next value; outside start/data it holds. Unknown state recovers to idle.

`rx_data_o` always exposes the stored byte, including before valid; `rx_valid_o` is high only in save. There is no framing-error, overrun flag or buffering of a following frame while stalled.
