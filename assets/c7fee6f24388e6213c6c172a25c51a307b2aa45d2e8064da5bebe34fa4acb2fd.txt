# FP_SUM_BLOCK_pipe_p15

## Interface

Inputs are `nvdla_core_clk`, active-low reset `nvdla_core_rstn`, 32-bit payload `stage3_pipe_in_pd_d2`, upstream valid `stage3_pipe_in_vld_d2`, and downstream ready `stage3_pipe_in_rdy_d3`. Outputs are 32-bit payload `stage3_pipe_in_pd_d3`, downstream valid `stage3_pipe_in_vld_d3`, and upstream ready `stage3_pipe_in_rdy_d2`.

## Behavior

This is a one-entry ready/valid pipeline register. Combinationally, upstream ready is `stage3_pipe_in_rdy_d3 || !stage3_pipe_in_vld_d3`. The output payload is the stored payload and output valid is the stored valid bit. When upstream ready is high, the rising edge captures `stage3_pipe_in_vld_d2` into the valid bit; if input valid is also high, it captures the input payload. When upstream ready is low, valid and payload are held. This permits replacement on the same edge that the downstream accepts the old item and supports one transfer per cycle.

The valid bit clears asynchronously when `nvdla_core_rstn` goes low. The payload register is not reset, so its value is unspecified while output valid is low. With an empty stage and asserted input valid, the item becomes visible after the next rising edge, giving one-cycle registered latency. Optional simulation assertions may check controls for unknown values and require an upstream producer to hold valid while stalled.
