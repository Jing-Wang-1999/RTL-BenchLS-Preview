# Implement the signed fixed-width PID controller project
Read the original project manual and implement every declared module in its
required file. The fixed configuration uses a 32-bit Wishbone data port, 16-bit
byte address, signed 16-bit coefficients and inputs, and wrapping 32-bit results.
The pinned defines header is expanded privately; no includes are required.

Behavior and timing clarifications:
- PID reset is active-high asynchronous. The multiplier's i_rst is active-low
  asynchronous. PID uses a 32-bit adder and a pipelined signed 16x16 multiplier.
- Registers at byte addresses 0,4,8,12,16 are Kp,Ki,Kd,SP,PV, written from low
  16 bits and sign-extended on reads. Writing Kp or Kd updates Kpd=Kp+Kd (wrap
  16 bits). Writing PV starts an update. Read-only Kpd,error,negative previous
  error,u,sigma,overflow are at 20,24,28,32,36,40. Address 44 accepts zero to
  clear error,u,sigma and overflow, preserving gains/SP/PV. Hardware reset clears all.
- e=wrap16(SP-PV); previous term=wrap16(-old_e). Then sigma=wrap32(sigma+Ki*e),
  u=wrap32(Kpd*e+sigma+Kd*previous_term). Coefficients/errors multiply as signed
  integers. Arithmetic wraps, without saturation or implicit fixed-point shifts.
- Wishbone requests hold address/data/control until ACK. Writes acknowledge
  after request registration; write ACK stays high until STB drops. Reads ACK
  combinationally when the requested register is unlocked. Gain writes/reads
  and state reads can wait while arithmetic locks are active. No exact internal
  FSM encoding is required; complete an update within 20 input clocks after PV
  acceptance. o_valid=1 means output/state are not busy (including reset/idle),
  not a one-cycle completion pulse. Results hold between updates.
- Overflow flags are Kpd[0], current error[1], previous error's flag[2], u[3],
  sigma[4]. Kpd/current error flags update on the corresponding calculations;
  sigma accumulation overflow is sticky, and u includes that sticky flag plus
  overflow from its two subsequent additions. Reset/RS clears flags.
- multiplier_16x16bit_pipelined accepts operands whenever i_start=1. Product and
  o_ready correspond to the previous clock's accepted operands: two register
  stages, one new product each clock under sustained start. Ready carries bubbles.
  adder_32bit computes the 33-bit unsigned sum including carry-in.
- booth_radix4 maps triplets 000..111 to digits 0,+1,+1,+2,-2,-1,-1,0 via
  zero, double(abs digit=2), negation(digit<0). booth_array applies this to eight
  overlapping radix-4 slices, appending zero below the multiplier's LSB.
  half/full adders and compressor42 preserve the binary weighted sum (S weight1,
  carry/cout weight2). Prefix operators A produce bit propagate/generate,
  B combines two groups, C combines a group with a preceding generate.
  partial_product_gen emits a 17-bit Booth partial with inverted sign bit, no
  negation correction bit: complement md when negating, zero when zero-select,
  sign-extend to 17 bits with inverted sign, and shift once for double, inserting
  the negation bit at the low end. These utility interfaces remain required.

Private points check Booth encoding, carry arithmetic, streamed signed products,
PID sequences and software reset. Finite tests sample behavior; no universal
equivalence or exhaustive overflow coverage is claimed. Public checks compile only.

Implement every required path in output_contract.json. Declaration-only ports
are in interfaces/modules.v. No initial/final, delays, simulation system tasks,
force/release or external includes are permitted. Only declared RTL is collected.
Missing files, forbidden constructs or failed top compilation score zero. Each
private point has equal weight and requires all of its checks to pass. Use
terminal/file_editor, iverilog, vvp and Python iteratively; finish by saving RTL.
Run `python3 checks/check.py` for public compilation feedback.
