**Module Specification: Dual-Clock Data Buffer with Synchronization**

**Overview**
This module is a 7-bit wide data transfer unit that operates across two independent clock domains. It accepts data in one clock domain, provides a synchronized copy in the same domain, and transfers a synchronized version to a second clock domain. The design includes a simple two-stage synchronizer for cross-clock data transfer.

**Interface Signals**

*Inputs*
- **iclk_i**: Primary input clock.
- **iclk_reset_i**: Synchronous reset for the primary clock domain (active high). This reset clears the primary domain’s output register.
- **oclk_i**: Output clock, asynchronous to `iclk_i`.
- **iclk_data_i[6:0]**: 7-bit data input sampled in the primary clock domain.

*Outputs*
- **iclk_data_o[6:0]**: 7-bit registered output in the primary clock domain. This is a delayed copy of the input data.
- **oclk_data_o[6:0]**: 7-bit synchronized output in the secondary clock domain.

**Functional Description**

1. **Primary Clock Domain Operation**
   - On every rising edge of `iclk_i`:
     - If `iclk_reset_i` is asserted (high), the `iclk_data_o` register is cleared to all zeros.
     - Otherwise, the value on `iclk_data_i` is captured and stored in the `iclk_data_o` register. This register directly drives the `iclk_data_o` output.

2. **Cross-Clock Domain Transfer**
   - The module implements a two-stage synchronizer to safely transfer the 7-bit data from the primary clock domain (`iclk_i`) to the secondary clock domain (`oclk_i`).
   - On every rising edge of `oclk_i`:
     - The first synchronization stage (internal register `bsg_SYNC_1_r`) samples the current `iclk_data_o` value.
     - The second synchronization stage samples the value from the first stage and presents it as `oclk_data_o`.

**Key Characteristics**
- The data path is 7 bits wide.
- The primary domain output (`iclk_data_o`) is a simple register with synchronous reset.
- The cross-clock transfer uses a double-register synchronizer (two flip-flop stages) per bit to mitigate metastability risks.
- No reset is applied in the secondary clock domain; the synchronizer registers initialize to unknown values.
- The module assumes no relationship between `iclk_i` and `oclk_i` (they are asynchronous).

**Allowed Sub-modules**
The implementation may use standard flip-flops and registers. No other sub-modules are required beyond these basic storage elements.

**Timing**
- Setup and hold times must be respected for `iclk_data_i` relative to `iclk_i`.
- The transfer latency to `oclk_data_o` is at least two `oclk_i` cycles after `iclk_data_o` is stable, plus any propagation delay.
