# pcie_us_axil_master: default-configuration specification

Implement the module interface below. All arithmetic is fixed-width unsigned unless explicitly stated. Sequential updates use pre-edge values and occur on the stated clock edge. Preserve externally observable cycle timing, including outputs outside valid transactions wherever defined. No golden RTL is provided to the implementation model.

## Default configuration and interfaces

Bridge UltraScale PCIe CQ requests to one 32-bit AXI-Lite access and emit CC completions. Defaults: PCIe data256, keep8 (one bit per DWORD), CQ user85, CC user33, AXI data32/address64/strobes4, parity disabled. Other width/parity parameter values are not qualified. Sole rising `clk`, synchronous high `rst`. AXI address protection outputs are permanently010. CQ keep is ignored; CQ user bits7:0 alone supply byte enables; AXI RRESP/BRESP are ignored, so even an AXI error response does not produce a PCIe error. The module provides no timeout or outstanding-request ID support.

Reset clears FSM to idle, CQ ready, AXI AW/W/AR valids and B/R readies, status pulses, and both CC output-buffer valid flags/internal ready. Request metadata, address/data/strobes and CC buffer payloads have no reset assignment; they can update under their normal enables during reset. Their declaration initializers are not reset promises. All public outputs are continuously driven from their corresponding registers; invalid payloads are not forced zero.

## CQ format and supported requests

Accept CQ only on valid&&registered ready. In idle capture aligned address `{tdata[63:2],00}`, DWORD count74:64, request type78:75, requester ID95:80, tag103:96, traffic class123:121, attributes126:124, first BE user3:0, last BE user7:4, and write word159:128. AWADDR and ARADDR share the captured address register; WSTRB is first BE, WDATA is the captured word. Last BE is retained but has no functional role for the supported one-DWORD operations.

Types0 memory read,1 memory write,2 I/O read,3 I/O write are supported only when count=1 and the first CQ beat is also last. Accepted read raises ARVALID and enters read-response state; accepted write raises AWVALID/WVALID independently and enters write-response state. No new CQ request is accepted while waiting for that response. Each AXI valid remains high until its own ready is observed. AXI slaves are expected to produce their B/R response according to AXI channel ordering; no extra formal traffic assumptions may be inserted to hide arbitrary input behavior.

Malformed reads and I/O writes produce a correctable status pulse and completer-abort completion status4, without AXI access. Malformed memory writes produce an uncorrectable pulse and no completion. Unsupported request types produce status1 (unsupported request); types12..15 are treated as posted messages, causing uncorrectable pulse/no completion, and other unsupported types produce a correctable pulse and completion. Pulses are registered one-clock flags, default0 each cycle. If the rejected first beat is not last, drain CQ until a last-beat handshake before completing or returning idle.

## CC completion format

Every completion fits one256-bit beat, last=1 and user33'b0. Data starts all zero, then fills these fields:

| Bits | Value |
|---|---|
| 6:0 | captured address6:2 concatenated with index of lowest set first-BE bit; zero low2 if BE=0 |
| 9:8 | 0 |
| 28:16 | byte-count span described below, except explicit error-completion state sets0 |
| 42:32 | 1 for read data,0 for no-data completion |
| 45:43 | success0, unsupported1 or abort4 |
| 63:48 | requester ID |
| 71:64 | tag |
| 87:72 | live completer_id at internal completion acceptance |
| 88 | live completer_id_enable |
| 91:89 | captured traffic class |
| 94:92 | captured attributes |
| 95 | 0 |
| 127:96 | live AXI RDATA at internal completion acceptance, including when keep masks this word |
| 255:128 and other unlisted bits | 0 |

Byte count is1 for BE0 or any single set bit;2 for0011,0110,1100;3 for0101,0111,1010,1110;4 for1001,1011,1101,1111. Thus it is enabled-byte span, not population count. Read success has keep0F and count1. I/O write success has keep07 and count0; its byte count is the BE-derived value. Memory write success emits no CC completion. AXI response error codes do not change success status.

Rejected one-beat nonposted requests enter the explicit completion state, which sets byte count0/keep07/DWORD count0. A rejected multi-beat nonposted request first attempts to emit directly on its final drained beat with BE-derived byte count and its stored error status; if internal ready is false it retries through the explicit completion state, which sets byte count0. Preserve this path-dependent byte-count behavior. The upper AXI read-data word remains present but masked when keep07.

## Cycle scheduling and CC skid buffer

Internal CC payload has defined values even without a valid offer: default keep0F, last0, DWORD count1, BE-derived byte count, stored status, request metadata and live RDATA in bits127:96 as in the format table. READ state overrides last1 and success status even without an AXI response. Completion states override these defaults as described above. Invalid internal payloads can therefore be captured by the skid buffer and must not be replaced with zero.

Maintain a CC output register and one temporary register. Let output valid=V, temp valid=U, sink ready=R, and registered internal ready=Q. Early-ready E is `R || (!U && !V)`, registered into Q every nonreset edge. An internal completion offer is accepted only when old Q=1. When Q=1 and (R or !V), transfer the entire internal payload and its valid into output, even if internal valid0. When Q=1 and stalled valid output, transfer payload/valid to temp. When Q=0 and R=1, move temp payload/valid to output and clear temp valid. Otherwise hold both. Reset overrides validity/Q only. This preserves valid output payload under backpressure, while invalid payload registers can change.

Idle schedules next CQ-ready=E. On a valid read handshake it instead sets next CQ-ready0, ARVALID1 and RREADY=E. Read state continuously schedules RREADY=E. An RVALID&&old-RREADY handshake offers the read completion, clears next RREADY and returns idle with next CQ-ready=E. Valid read response data is sampled through the CC buffer that same edge, rather than latched in a separate read-data register.

A valid write handshake sets next CQ-ready0, AWVALID/WVALID1 and BREADY1. Write-response state thereafter schedules BREADY=E. BVALID&&old-BREADY clears BREADY and either returns idle without CC for memory write or offers the I/O completion and returns idle. AW/W/AR valid-clear logic runs independently in every state; no extra clearing is implied by state exit.

The rejected-packet drain state schedules CQ-ready1 continuously. On final handshake, posted types return idle. Nonposted types offer a no-data completion; if Q=1 return idle, otherwise enter explicit completion state. That state offers its error completion every cycle until Q=1. CQ-ready remains0 during explicit completion. Reset can interrupt every transaction.

The width64-specific header and second-completion states and width128 write-payload state are not reachable from reset at declared defaults. Qualify the default behavior above, not the source-line count contributed by those inactive branches.
